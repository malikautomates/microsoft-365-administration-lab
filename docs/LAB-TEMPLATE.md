# Lab NN — Title

**Objective:** One sentence stating the outcome the lab produces.
**Environment:** Hosts involved and their roles.
**Prerequisites:** Labs that must be complete before this one.
**Starting checkpoint:** Named virtual machine checkpoint this lab begins from.
**Duration:** Approximate time to complete.

---

## 1. Scenario

Two to four sentences framing the task as operational work rather than an exercise: the
requirement, who raised it, and the constraint that shapes the solution. This section
establishes why the configuration is being made.

---

## 2. Design decisions

For each decision where more than one valid approach exists:

| Decision | Options considered | Selected | Rationale |
|---|---|---|---|
| | | | |

Decisions with a single correct answer do not belong here. This section is reserved for
choices that a reviewer could reasonably question.

---

## 3. Implementation

Numbered steps. Each step states the action, the command or interface path, and the expected
result.

PowerShell is given as the primary method. Where a graphical equivalent exists and is likely
to be used in practice, it is given as an alternative rather than as the primary path.

Screenshots are placed immediately after the step they evidence, using the convention:

```markdown
![Concise description of what the image shows](images/NN-nn-short-name.png)
```

Image filenames follow `NN-nn-short-name.png`, where `NN` is the lab number and `nn` is the
step number.

---

## 4. Verification

The commands used to confirm the intended state, with their output. Each verification states
what result constitutes success.

| Check | Command | Expected result |
|---|---|---|
| | | |

Verification output is included as text where the output is short, and as a screenshot where
the visual context of the console or console tool is relevant.

---

## 5. Faults encountered

For each fault observed during the build:

**Symptom.** The observable behaviour, including the exact error text or event ID.
**Diagnosis.** The commands or logs used to isolate the cause, in the order used.
**Cause.** The underlying condition.
**Resolution.** The change made, and the verification confirming it.

Where a fault was induced deliberately to document it, that is stated.

---

## 6. Capabilities demonstrated

A short list mapping the lab to recognised administrative capabilities. Written in the
vocabulary used in job descriptions, without overstatement.

---

## 7. References

Vendor documentation consulted, with the specific behaviour each source was used to confirm.
